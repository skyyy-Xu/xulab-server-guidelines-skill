# SSH 会话与自动化连接规范

## 背景

AI 进行服务器操作时，如果频繁新建 SSH、端口转发或让 subagent/自动巡检分别连接服务器，会在登录节点上留下大量 `sshd-session`。这些进程不等于历史登录次数，但会增加服务器管理负担。后续必须把 SSH 当作受控资源管理。

## 会话数量限制

- 主 agent 同一时间最多保留 1 个交互式 SSH 会话。
- 网页预览最多额外保留 1 个端口转发会话，例如 `ssh -L 8090:127.0.0.1:8090 ...`。
- subagent 默认不得直接 SSH 到 xulab；服务器操作由主 agent 统一提交 Slurm 或统一做一次合并检查。
- 禁止 heartbeat/subagent 高频 SSH 轮询。长任务状态由 Slurm 日志、结果文件和用户手动唤醒检查。

## 退出要求

普通交互 SSH 结束时必须显式退出：

```bash
exit
```

如果从登录节点进入计算节点，需要逐层退出：

```bash
exit  # 退出计算节点
exit  # 退出登录节点
```

端口转发用完必须关闭。优先在隧道窗口执行：

```bash
exit
```

或按 `Ctrl-C` 结束前台隧道。

非交互式 SSH 命令必须设计为命令执行完自动退出；不得用 `tail -f`、长时间 `watch` 或无限循环占住 SSH 会话。

## 状态检查方式

- 状态检查必须合并：一次 SSH 内完成 `squeue`、日志、结果文件、网页预览状态等只读检查。
- 不把同一状态检查拆成多个独立 SSH。
- 长任务提交后必须告诉用户预计多久后人工唤醒，不依赖 agent 自动轮询。
- 若任务完成或失败，报告 `RUN_ID`、Slurm job id、日志路径、结果目录和下一步建议。

## 结束前自查

本机检查是否还有残留 SSH：

```bash
ps aux | grep -E 'ssh .*10\.126\.82\.10|ssh .*xulab|ssh .*cernet2|ssh -L 8090' | grep -v grep
```

服务器端如需排查本人残留会话，只列明细，不直接全杀：

```bash
ps -u "$USER" -o pid,ppid,stat,lstart,cmd | grep '[s]shd'
who -u
```

清理前必须确认不影响当前登录、老师排查会话和 Slurm 作业。Slurm 作业通常不依赖 SSH 会话维持，不能用杀 SSH 的方式替代 `scancel` 管理作业。

## 事故处理

如果发现本人名下 `sshd-session` 异常增多：

1. 立即停止新的服务器连接和自动化检查。
2. 先关闭本机旧 SSH 终端和端口转发。
3. 请求管理员或用户列出本人名下 SSH 会话明细。
4. 只清理确认无用的旧 SSH 会话，不杀 Slurm 作业。
5. 复盘是哪类脚本、subagent 或端口转发造成残留，并更新流程。
